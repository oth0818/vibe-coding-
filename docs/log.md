# 작업 기록

## Phase 0 — 나이브 베이스라인 (10/9)

### 진행 방식
- 저장소 안에 `phase0` 폴더를 만들고, 그 폴더에서 Claude Code(Sonnet)를 실행
- 첫 메시지는 한 줄만, 이후에는 내용 없는 메시지("계속해줘" 등)만 보냄
- AI가 중간에 "마음에 안 드는 점을 말해달라", "log.md를 정리해 드릴까요"라고 물었지만 답하지 않음

### 보낸 메시지 (원문 그대로)
1. 공강 시간에 갈 수 있는 곳 알려주는 웹앱 만들어줘
2. 계속해줘
3. 더 좋게 만들어줘
4. 완성해줘

### 턴별 결과

**1턴**
- `phase0/index.html` 단일 정적 페이지 생성. 장소는 localStorage에 저장
- 공강을 "분"으로 입력하거나 30분 / 1시간 / 1시간 30분 / 2시간 버튼으로 고름
- 목적 필터 6개: 밥, 카페, 공부, 쉬기, 운동, 구경
- 판정: 왕복 이동 + 머무는 시간을 더해 "여유(10분 이상) / 빠듯(0~9분) / 부족"
- AI 스스로 "브라우저에서 열어 동작을 확인하지는 못했다"고 말함

**2턴**
- 브라우저 대신 node로 문법 검사만 하고 "syntax ok"로 확인
- 명령 실행이 "Allowed by auto mode classifier"로 표시됨. 내가 하나하나 승인하지 않았는데 자동으로 실행됨
- 요청하지 않은 기능 2개 추가
  - 공강을 시작~종료 시각으로도 입력
  - 맨 위 "지금 추천" 카드: 갈 수 있는 곳 중 여유 시간이 가장 적은("딱 맞는") 곳을 추천
- AI가 스스로 "추천 기준은 요청하지 않은 결정"이라고 밝힘

**브라우저 확인 (2턴 후)**
- 정상으로 열리고 목록이 표시됨
- 공강 60분일 때 "지금 추천"이 중앙도서관(60분 중 59분 쓰고 1분 남음)
- 공강 120분일 때 "지금 추천"이 스터디카페(80분 쓰고 40분 남음)
- 목록이 여유가 적은 순서로 정렬되어 "빠듯(1분 남음)", "빠듯(4분 남음)"이 맨 위에 옴

**3턴**
- AI가 "눈에 띄는 약점"으로 보안과 저장을 먼저 고침
  - XSS: 장소 이름이 innerHTML로 그대로 들어가 `<img onerror=...>` 같은 입력이 실행될 수 있던 문제를 이스케이프로 수정
  - 새로고침하면 공강 시간과 필터가 초기화되던 문제를 localStorage 저장으로 수정
- 요청하지 않은 기능 3개 추가: 즐겨찾기(★), 다크모드(기기 설정을 따름), "예시 장소로 초기화" 버튼
- 이번에도 문법 검사만 하고 "브라우저에서 직접 열어 보지는 못했다"고 말함
- 남은 한계를 스스로 나열함: 장소 수정 기능 없음, 도보 시간 직접 입력, 영업시간 미반영, 시간표 연동 없음
- "60분 공강에 1분 남는 곳 추천" 문제는 고치지 않음. "갈 수 있는 곳이 위쪽이라는 순서는 그대로"라고 함
- 끝에 다시 "원래 생각하던 것과 어디가 다른지 말해주면 다음 턴에 반영하겠다"고 물음

**브라우저 확인 (3턴 후)**
- 기기가 다크모드라 다크 화면으로 열림
- 공강 시간 버튼(30분, 1시간, 1시간 30분, 2시간)과 카테고리 버튼(밥, 카페, 공부 등)이 흰 배경에 흰색에 가까운 글자라 **글자가 거의 안 보임**
- 60분일 때 "지금 추천"은 여전히 중앙도서관(1분 남음)
- 분 칸을 90으로 바꿔도 시각 칸은 12:00~13:00(60분) 그대로. 두 입력이 계속 안 맞음
- 90분일 때 추천은 스터디카페(10분 남음)

**4턴**
- AI가 "지난 턴에 남긴 약점 중 핵심 두 가지"로 장소 수정 기능과 영업시간을 골라 작업 시작
- 작업 중 AI 실수: 파이썬으로 코드를 문자열로 잘라 붙이다가 Traceback이 나고, 이어서 파일 일부가 중복돼 `SyntaxError: Unexpected token 'if'` 발생. 문법 검사로 발견하고 스스로 복구함. AI도 "제 실수가 하나 있었다"고 인정
- 이번엔 처음으로 jsdom(가상 브라우저)으로 동작을 확인함. 그 과정에서 "1분밖에 안 남은 곳이 추천 1위로 뜨는 문제"를 AI가 스스로 발견하고 "여유 10분 이상인 곳을 먼저 추천"하도록 바꿈
- 추가한 것: 장소 수정, 영업시간(장소에 영업시간을 넣고, 도착 시각이 영업시간 밖이면 "영업시간 아님"으로 표시하고 추천에서 뺌), 시작 시각·분 버튼·종료 시각 연동
- 예시 장소 중 학생식당, 교내 카페, 중앙도서관에 영업시간을 AI가 임의로 넣음 (예: 중앙도서관 09:00~22:00)
- 여전히 남은 것으로 스스로 밝힘: 장소 데이터는 예시값, 도보 시간 직접 입력, 지도 연동 없음, 시간표 연동 없음
- 실제 브라우저로는 여전히 열어보지 않음 ("jsdom으로 확인했지만 실제 브라우저에서 화면을 직접 열어 보지는 못했다")
- 커밋과 푸시는 "요청하시기 전에는 하지 않았다"며 하지 않음

**브라우저 확인 (4턴 후)**
- 분 칸과 시각 칸 연동이 고쳐짐: 90분을 누르면 12:00~13:30으로 바뀜
- 공강 90분, 전체: 추천이 스터디카페(80분 쓰고 10분 남음). 여유 10분 이상 중에서 여전히 가장 빠듯한 곳을 고름
- 공강 90분, 쉬기: 추천이 학생회관 휴게실(52분 남음). 더 여유 있는 잔디밭 벤치(64분 남음)가 아니라 덜 여유 있는 곳을 추천
- 다크모드에서 버튼 글자가 안 보이는 문제는 그대로. jsdom은 색을 보지 않으니 AI가 발견하지 못함
- 카드마다 "수정" 버튼이 생기고, "+ 내 장소 추가하기"가 접힌 형태로 들어감

### AI가 요청하지 않았는데 임의로 정한 것
- 장소 데이터: 실제 캠퍼스 데이터가 아닌 가짜 이름 (학생식당, 중앙도서관, 정문 앞 카페거리, 교문 앞 분식집, 호수/연못, 스터디카페, 체육관, 학생회관 휴게실, 교내 카페 등)
- 도보 시간: 지도나 위치 없이 장소마다 "왕복 N분"을 고정값으로 넣음
- 장소별 머무는 시간: 도서관 45분, 분식집 30분, 스터디카페 60분 등
- 판정 기준: 여유 10분 이상 / 빠듯 0~9분이라는 숫자
- 목적 카테고리 6개, 이모지, 색상
- 추천 기준: "여유가 가장 적은 곳"을 가장 좋은 곳으로 봄 (2턴)
- "더 좋게"의 의미: 사용성(추천이 엉뚱함)이 아니라 보안(XSS), 저장, 즐겨찾기, 다크모드를 우선으로 봄 (3턴)
- "완성"의 의미: 장소 수정과 영업시간을 "핵심 약점"으로 골라 추가함 (4턴)
- 예시 장소의 영업시간 (4턴)
- 바뀐 추천 기준: "여유 10분 이상인 곳 중 가장 빠듯한 곳" (4턴)
- 반영하지 않은 것: 시간표, 출발 강의실과 다음 강의실, 층과 엘리베이터 (영업시간은 4턴에 추가)

### 동작한다고 했지만 실제로는 안 된 것
- 다크모드: "기기 설정을 따른다"고 했지만, 다크 화면에서 버튼 글자가 배경과 같은 색이라 읽을 수 없음. 3턴에 생겨서 4턴 "완성" 후에도 그대로. 문법 검사와 jsdom으로는 색을 볼 수 없어서 AI가 끝까지 발견하지 못함
- 분 칸과 시각 칸이 서로 안 맞음 (2~3턴): 분 칸은 120이나 90인데 시각은 12:00~13:00(60분)으로 그대로. 4턴에 AI가 연동을 추가해 해결됨
- (장소 추가 후 새로고침해서 남는지: 확인 예정)

### 내가 원한 것과 다르게 만들어진 것
- 공강 60분일 때 여유 1분짜리 곳을 1등으로 추천함. 조금만 늦어도 지각. 3턴 후에도 그대로였고, 4턴에 AI가 jsdom 테스트로 스스로 발견해 "여유 10분 이상 먼저"로 바꿈. 하지만 그 안에서는 여전히 가장 빠듯한 곳을 추천(쉬기: 52분 남는 곳 > 64분 남는 곳)
- 목록이 빠듯한 곳부터 정렬됨 (4턴 후에는 여유 10분 이상인 곳 중 빠듯한 순)
- 장소가 실제 중앙대 안성캠퍼스와 무관함
- 출발 강의실, 다음 강의실, 층, 엘리베이터 없이 "왕복 N분"만 있음

### 그중 문제가 된 것 / 문제가 안 된 것 (초안, 직접 확인해서 고칠 것)
- 문제 됨: "딱 맞는 곳" 추천 기준 → 여유 1분짜리를 추천. 실제로 쓰면 지각
- 문제 됨: 가짜 장소 데이터 → 실제 캠퍼스에서 쓸 수 없음
- 문제 안 됨: 단일 HTML + localStorage 구조 → GitHub Pages에 그대로 올릴 수 있음. 내가 원한 방식과 같음
- 문제 됨: 다크모드 → 요청하지 않았는데 추가했고, 추가하면서 버튼 글자가 안 보이게 됨
- 문제 안 됨: 화면 디자인(라이트 모드) → 깔끔해서 손댈 필요 없음
- 문제 안 됨: XSS 수정 → 요청하지 않았지만 맞는 수정. 내가 놓쳤을 부분
- 문제 안 됨: 시각과 분 연동 (4턴) → 내가 보고 불편했던 부분을 AI가 스스로 고침
- 문제 됨(작게): 예시 장소 영업시간을 지어냄 → 실제 값이 아니라 그대로 믿으면 안 됨

### 그 밖의 발견
- AI가 저장소의 README.md와 presentation.md를 읽고 과제 규칙(Phase 0, 3~5턴, 성찰기)을 이미 알고 있었음. "성찰기에 쓸 만한 것들", "Phase 0 기준으로 2턴" 같은 말을 함. 그래서 이 베이스라인은 완전히 맥락 없는 상태가 아니었음
- AI가 `prototype/index.html`이 있다는 걸 알았지만 "베이스라인이 오염되지 않도록 참고하지 않았다"고 말함 (실제로 안 봤는지는 확인 못 함)
- 2턴에서 "문법 검사 통과"를 근거로 수정이 끝났다고 했지만, 브라우저 동작은 여전히 확인하지 않음
- 2턴에서 README 금지 항목인 "추천 알고리즘"에 가까운 기능을 스스로 추가함
- 매 턴 끝에 "docs/log.md에 관찰 기록을 정리해 드릴 수 있다"고 제안하거나 피드백을 달라고 함
- 세 턴 모두 브라우저로 확인하지 않고 문법 검사(node)만으로 "개선했다"고 보고함. 실제 화면 문제(다크모드 글자, 입력 불일치, 엉뚱한 추천)는 전부 브라우저를 열어야 보였음
- "더 좋게"라는 막연한 요청에 AI는 기능을 늘리는 쪽(즐겨찾기, 다크모드, 초기화)으로 갔고, 새 기능이 새 문제(다크모드 글자)를 만듦
- AI의 확인 방식이 턴마다 달라짐: 1턴 확인 없음 → 2~3턴 문법 검사 → 4턴 jsdom 동작 테스트. 실제로 실행해본 4턴에야 "1분 남은 곳 추천" 문제를 스스로 찾음. 즉 **AI는 실행해보는 만큼만 문제를 찾고, 실행 환경이 못 보는 것(색, 가독성)은 끝까지 못 찾음**
- 4턴에서 코드를 문자열로 잘라 붙이다가 파일을 깨뜨리고 스스로 복구함. 큰 파일을 덧붙이는 방식으로 고치면 깨질 위험이 있음
- 커밋과 푸시는 요청 전엔 하지 않음 (권한 범위를 지킴)

### 슬라이드 3 후보 (AI가 임의로 정한 것 3가지)
1. 가짜 장소 데이터: 실제 장소를 하나도 모르는 상태에서 장소를 지어냄
2. "딱 맞는 곳"을 추천 기준으로 정함: 60분 공강에 1분 남는 곳을 1등으로 추천
3. 실제 브라우저 확인 없이 "완료": 네 턴 모두 실제 브라우저로 열어보지 않음. 문법 검사와 jsdom으로는 색을 볼 수 없어서 다크모드에서 버튼 글자가 안 보이는 문제를 끝까지 놓침

(대안 후보: "더 좋게"를 보안과 기능 추가로 해석함. XSS 수정은 맞았지만 다크모드는 새 문제를 만듦 → 문제 된 것과 안 된 것을 같이 보여줄 수 있음)

### Phase 0에서 얻은 교훈 (CLAUDE.md에 반영할 것)
- 장소, 도보 시간, 판정 기준 같은 값은 내가 정해서 적어주지 않으면 AI가 지어낸다
- "추천", "좋은 곳" 같은 말은 기준을 숫자로 정해주지 않으면 AI가 이상한 기준을 만든다
- AI에게 "브라우저에서 확인했다"는 걸 믿지 말고, 화면은 내가 직접 연다
- 막연한 요청("더 좋게", "완성해줘")은 기능을 늘리게 만든다. 한 번에 하나씩 구체적으로 요청한다

### 보낸 메시지 (원문 그대로)
1. docs/requirements.md를 읽고 이 프로젝트의 CLAUDE.md 초안을 저장소 맨 위에 써줘. 요구사항에 없는 내용은 지어내지 말고, 애매한 부분이 있으면 쓰기 전에 나한테 물어봐. 코드는 아직 쓰지 마.
2. (AI 질문에 대한 답, 아래 참고)
3. CLAUDE.md를 읽어보니 네 군데를 고쳐야 해.
   1. 다크모드는 만들지 않아. "표시 원칙"의 라이트·다크 문장을 "화면은 라이트 모드로 고정한다(color-scheme: light). 기기가 다크모드여도 글자가 배경과 충분히 구분돼야 한다"로 바꿔.
   2. 지도에서 새로 고른 곳과 검색 결과는 공강 화면의 머물 시간 입력값으로 판정하고, 저장하면 그 값이 장소의 머물 시간이 된다고 적어줘. 저장한 곳은 자기 머물 시간을 쓴다.
   3. 갈 수 있는 범위 원의 중심은 앞 수업 건물이라고 적어줘.
   4. 시간표 화면에서 수업을 추가하고 삭제할 수 있게 해. 입력 항목은 요일, 과목, 건물, 호실, 시작, 끝이고, 건물은 목록(원형관, 중앙문화관)에서 고르고, 층은 호실 앞자리로 계산해. 기본값은 지금 내 시간표로 두고, 저장은 localStorage에 해.
   고친 부분만 보여주고, 코드는 아직 쓰지 마.

### AI가 쓰기 전에 물어본 것 (3개)과 내 답
| AI 질문 | 내 답 |
|---|---|
| 장소는 어떻게 고르고 저장하나? 문서에 "지도에서 고른다"와 "가게 검색"은 있는데, 지도 빈 곳을 직접 찍는 건 언급이 없음 | (직접 입력) 지도 빈 곳 클릭도 허용해. 누른 곳은 바로 "지도에서 고른 곳"으로 판정하고, 저장 버튼을 누를 때 이름을 입력받아. 검색에 안 나오는 학교 앞 작은 가게 때문에 필요해. |
| 지금 모드에서 오늘이 공강이 없는 날이거나 지금이 공강 시간이 아닐 때는? | 요일 선택대로 계산 (보기 중 1번) |
| 영업시간 판정의 "도착 시각"은 어떻게 잡나? | 시작 시각 + 가는 시간 (보기 중 1번) |

- 세 질문 모두 "CLAUDE.md에 적지 않음(나중에 다시 묻기)" 보기가 있었지만 고르지 않음. 비워두면 기능 만들 때 AI가 정해버릴 수 있어서

### AI 초안 결과
- requirements.md 내용을 순서대로 옮기고, 세 답을 반영해 78줄짜리 CLAUDE.md 작성

- 요구사항에 없던 문장 1개("요구사항에 없는 내용은 지어내지 말고, 애매하면 먼저 물어본다")를 추가하고 스스로 밝힘. 내용이 맞아서 그대로 둠 → **개입하지 않음**
- "README.md는 열어보지 않았고, docs/log.md는 건드리지 않았다"고 보고함

### 내가 초안을 읽고 고친 것 (개입함)
- **다크모드 모순:** "표시 원칙"에는 "라이트·다크 둘 다 글자 구분", "작업 방식"에는 "다크모드 추가 금지". 요구사항을 정리할 때 내가 만든 모순이었고 AI도 묻지 않음 → 라이트 모드 고정으로 정리
- **머물 시간이 두 군데:** 공강 화면 입력값과 장소별 값 중 새로 고른 곳은 무엇을 쓸지 빠져 있었음 → 입력값으로 판정, 저장하면 장소 값이 됨
- **범위 원의 중심이 없음** → 앞 수업 건물
- **시간표 보기만 가능** → 다른 학생도 쓸 수 있게 수업 추가/삭제 추가 (실용성 고려). 화면 수는 3개 그대로
- AI는 네 군데를 diff로 보여주며 고쳤고, "데이터의 시간표는 기본값이 된다"는 점을 스스로 설명함

### Phase 0과 비교해서 달라진 점
- Phase 0: 아무것도 묻지 않고 장소, 기준, 추천 방식을 전부 정함
- Phase 1: 요구사항 문서와 "애매하면 물어봐" 한 문장을 주자, 쓰기 전에 빈칸 3개를 찾아 질문함
- 하지만 AI가 찾지 못한 빈칸과 모순(다크모드, 머물 시간 두 개, 원의 중심)은 내가 읽고 찾아야 했음. **AI는 "문서에 없는 것"은 잘 찾지만, "문서끼리 부딪히는 것"은 못 찾았음**
